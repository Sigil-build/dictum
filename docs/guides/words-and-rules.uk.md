# Ваші слова й правила заміни

Whisper добре знає поширені слова, але імена, назви продуктів і терміни він угадує: «авалонія» замість Avalonia, «нексус файв» замість Nexus5. Dictum має для цього два інструменти:

- **Ваші слова** діють *до* розпізнавання. Кожен профіль має список слів, і Dictum показує їх Whisper як підказку, тож той схиляється до вашого написання.
- **Правила заміни** діють *після* розпізнавання. Це обробник, який знаходить текст і замінює його саме так, як ви сказали.

Почніть із ваших слів. Правило заміни додавайте тоді, коли слово й далі щоразу виходить неправильно однаково.

## Ваші слова {#your-words}

### Як працюють ваші слова {#how-words-work}

Перед кожним диктуванням Dictum вставляє слова профілю в *підказку для розпізнавання* — короткий текст, який Whisper читає, перш ніж слухати. Тоді Whisper віддає перевагу цим написанням, коли звучання підходить.

- Підказка вміщує 400 символів разом із полем **Підказка для розпізнавання** профілю. Слова, що не влізли, пропускаються з кінця списку. Ставте найважливіші слова першими.
- Слова допомагають лише в тому профілі, до якого належать. Кожен профіль має власний список.
- Якщо мова профілю — **Авто**, список слів може тягти визначення мови до мови самого списку. Задайте мови профілю: див. [Мови](languages.md).
- Сервер розпізнавання отримує ту саму підказку в полі `prompt` запиту.
- Вбудовані запити до LLM ваших слів не використовують. Ваш власний запит може це робити через `{{vocabulary}}`: див. [Чищення тексту мовною моделлю](llm-cleanup.md#prompt).

### У майстрі налаштування {#words-in-wizard}

Крок 4 майстра налаштування — **Ваші слова**.

1. Введіть слова в поле, по одному в рядку, або вставте список через кому: **По одному в рядку, або вставте список через кому**.
2. Натисніть **Далі**.

Слова потрапляють у ваш перший профіль. Коли ви знову запускаєте майстер, поле показує список цього профілю, а після завершення список стає таким, яким він є в полі.

### У Налаштуваннях → Профілі {#words-in-profiles}

1. Відкрийте **Налаштування** → **Профілі** й виберіть профіль.
2. У розділі **Ваші слова** введіть слово в поле **Додайте слова — Enter або вставте список** і натисніть `Enter`. Щоб додати багато слів одразу, вставте список: по одному в рядку, через кому або крапку з комою.
3. Кожне слово стає плашкою. Хрестик на плашці прибирає слово. **Слів: 12** показує, скільки їх.

Слово, яке вже є в списку, в будь-якому регістрі, вдруге не додається.

**Підказка для розпізнавання** під словами — додатковий текст, який Whisper читає перед ними, наприклад речення в тому стилі, в якому ви диктуєте. Зазвичай її лишають порожньою.

### З командного рядка {#vocab-command}

!!! note
    У Windows інсталятор MSI не додає `dictum` до `PATH`. У PowerShell запускайте його за повним шляхом, наприклад `& "$env:LOCALAPPDATA\Programs\Dictum\dictum.exe" vocab list`. В AppImage допишіть `dictum` після назви файла: `./dictum-<version>-linux-x64.AppImage dictum vocab list`.

`dictum vocab` змінює список слів першого профілю або того, який ви вкажете через `--profile`. Запущений Dictum одразу підхоплює кожну зміну.

```sh
dictum vocab add Avalonia Nexus5 "VS Code"
dictum vocab list
dictum vocab remove "VS Code"
dictum vocab clear
dictum vocab add --profile profile Kubernetes
```

- `add` дописує слова в кінець списку. Фразу з пробілами беріть у лапки.
- `remove` прибирає слова в будь-якому регістрі й попереджає про ті, яких у списку не було.
- `clear` очищає список.
- `list` виводить список, по слову в рядку.

Після кожної зміни команда показує профіль і кількість слів, наприклад `dictate: 3 word(s)`.

Щоб додати багато слів із файла, запишіть їх по одному в рядку. Порожні рядки й рядки, що починаються з `#`, пропускаються:

```text
# Імена
Avalonia
Nexus5
Kubernetes
```

```sh
dictum vocab import words.txt
```

`dictum vocab import -` читає список зі стандартного входу.

Коли в підказці бракує місця, `dictum vocab` попереджає: `warning: the speech hint holds 400 characters, so these words are left out: …. Put the most important words first.`

## Правила заміни {#replace-rules}

### Обробник із правилами заміни {#create-rules}

1. Відкрийте **Налаштування** → **Обробники** й натисніть **+ Правила заміни**. Новий обробник матиме назву `rules` (далі `rules-2` і так далі).
2. Заповніть таблицю. Кожен рядок — одне правило:

    | Стовпець | Що він робить |
    | --- | --- |
    | **Знайти** | Текст, який треба знайти. |
    | **Регулярний вираз** | **Знайти** — регулярний вираз .NET, а не звичайний текст. |
    | **Замінити на** | Текст, який стане на його місце. Якщо поле порожнє, знайдене видаляється. |
    | **Враховувати регістр** | Для звичайного тексту: шукати лише в цьому самому регістрі. Без позначки `avalonia` знаходить і `Avalonia`. |
    | **Ціле слово** | Для звичайного тексту: шукати лише цілі слова, щоб `мейн` не чіпав `мейнфрейм`. |
    | **Увімк.** | Зніміть позначку, щоб правило лишилося в списку, але не застосовувалося. |

3. Щоб додати правило, почніть вводити в полі **Знайти** порожнього рядка внизу. Правила застосовуються по черзі, згори вниз.
4. Переконайтеся, що обробник запускає якийсь профіль. Новий обробник сам потрапляє в кожен профіль із порожнім ланцюжком обробки. Інакше список позначить його **Не в жодному профілі**: виберіть профіль у **Додати до профілю…**, як описано в [Чищенні тексту мовною моделлю](llm-cleanup.md#add-to-profile). Див. також [Розв'язання проблем](../troubleshooting.md#processor-in-no-profile).

Кілька правил, що виправляють написане Whisper:

| Знайти | Регулярний вираз | Замінити на | Враховувати регістр | Ціле слово |
| --- | --- | --- | --- | --- |
| `авалонія` | | `Avalonia` | | так |
| `нексус файв` | | `Nexus5` | | так |
| `(?i)\bвіжуал студіо\b` | так | `Visual Studio` | | |

Регулярний вираз живе за власними правилами: **Враховувати регістр** і **Ціле слово** на нього не впливають. Почніть його з `(?i)`, щоб не зважати на регістр, а межі слів позначайте `\b`. `$1` у полі **Замінити на** повертає першу групу в дужках. Регулярний вираз, якому на один текст треба понад 200 мс, пропускається.

### Імпорт правил із CSV {#import-csv}

**Імпорт із CSV…** додає правила з файла зі стовпцями «Знайти», «Замінити на» і, за бажанням, «Враховувати регістр» і «Ціле слово»:

```text
Знайти;Замінити на;Враховувати регістр;Ціле слово
авалонія;Avalonia;;так
нексус файв;Nexus5;;так
```

- Перший рядок, у якому перша клітинка — `Find` або `Знайти`, пропускається, як і порожні рядки.
- Клітинки розділяють комами або крапками з комою — тим, чого в першому рядку більше. Excel з українськими регіональними налаштуваннями пише крапку з комою.
- `true`, `yes`, `1`, `x`, `так` чи `+` ставить позначку.
- Імпортовані правила — звичайний текст, не регулярні вирази. Рядки, які не вдалося прочитати, називаються й пропускаються.

### Місце в ланцюжку обробки {#chain-order}

**Ланцюжок обробки** профілю виконує кроки згори вниз, і кожен крок отримує текст, який повернув попередній. Де стоять правила, важливо, коли профіль має ще й запит до LLM:

- **Правила перед запитом до LLM**: мовна модель бачить уже виправлені слова й ураховує їх.
- **Правила після запиту до LLM**: останнє слово за вашими правилами, хоч що написала модель.

Щоб змінити порядок, відкрийте **Налаштування** → **Профілі** й виберіть профіль. У розділі **Ланцюжок обробки** кожен крок показує свій номер, назву й тип, наприклад `rules` з **Правил: 3** і `cleanup` із **Запит до LLM**. Перетягніть крок за ручку або виділіть його й натисніть `Alt+↑` чи `Alt+↓`.

Щоб перевірити результат, проженіть текст через ланцюжок профілю:

```sh
dictum process "я будую інтерфейс на авалонія" --profile dictate
```

`--pipeline rules` запускає лише правила, а `--json` показує, скільки тривав кожен крок.
