# Початок роботи

Ця сторінка проведе вас від завантаження до першого диктування. Найбільше часу забирає завантаження моделі мовлення.

## Що потрібно {#requirements}

- **Windows 11 або Linux** на 64-бітному комп'ютері x86.
- **Процесор з AVX2:** Intel Haswell, AMD Zen або новіший. На старішому Dictum не запуститься.
- **Мікрофон.**
- **Місце на диску для моделі мовлення:** близько 265 МБ для моделі, яку майстер радить для процесора, і близько 875 МБ для тієї, яку він радить для відеокарти.
- **Відеокарта не обов'язкова.** Whisper працює на ній через Vulkan, якщо її драйвер це підтримує, а інакше — на процесорі. Для відеокарти майстер радить більшу модель, хіба що в карти менше 2 ГБ пам'яті.

У Linux знадобиться ще й таке:

- **glibc 2.38 або новіша для гарячих клавіш в X11:** Ubuntu 24.04, Fedora 39, актуальний Arch або новіші. Гарячі клавіші в X11 також потребують бібліотек libXtst, libXt, libXrandr і libxkbcommon, але в системі з робочим столом вони вже є.
- **Програма для буфера обміну, щоб вставляти текст:** `wl-clipboard` у Wayland, `xclip` або `xsel` в X11.
- **У Wayland — `xdg-desktop-portal`** разом із портальним модулем вашого робочого столу. KDE Plasma і GNOME встановлюють свої самі. Через портал Dictum просить гарячу клавішу й дозвіл натискати Ctrl+V: див. [Wayland і X11](#wayland-and-x11).
- **За бажанням:**
    - `xprop` в X11, щоб Dictum упізнавав термінал і вставляв у ньому через Ctrl+Shift+V;
    - GNOME Keyring або KWallet, щоб ключі API не лежали у файлі конфігурації;
    - `ydotool` або `wtype`, щоб натискати Ctrl+V у Wayland, коли робочий стіл не має порталу RemoteDesktop.

Програми для буфера обміну встановіть менеджером пакетів:

```sh
# Debian, Ubuntu
sudo apt install wl-clipboard xclip
# Fedora
sudo dnf install wl-clipboard xclip
# Arch, CachyOS
sudo pacman -S wl-clipboard xclip
```

## Завантаження {#download}

Завантажте Dictum зі [сторінки випусків](https://github.com/Sigil-build/dictum/releases/latest). Кожен випуск має такі файли, де `<version>` — версія випуску, наприклад `0.4.0`:

| Файл | Що це |
| --- | --- |
| `dictum-<version>-win-x64.msi` | Windows 11: інсталятор. Беріть його, якщо вам не потрібна саме версія без інсталятора. |
| `dictum-<version>-win-x64.zip` | Windows 11: ті самі програми без інсталятора. |
| `dictum-<version>-linux-x64.AppImage` | Linux: один файл, який запускається як є. |
| `dictum-<version>-linux-x64.tar.gz` | Linux: встановлюється для вашого користувача через `install.sh`. З нього ж збирається пакет для Arch. |
| `PKGBUILD` | Arch Linux і CachyOS: збирає з архіву пакет для pacman. |
| `SHA256SUMS` | Суми SHA-256 чотирьох пакетів `dictum-<version>`. |

## Перевірка завантаженого файлу {#check-download}

Перш ніж встановлювати, файл можна перевірити двома способами.

**Сума SHA-256.** У теці із завантаженнями порівняйте файл з його рядком у `SHA256SUMS`. У Linux ця команда пише `OK` після кожного знайденого файлу:

```sh
sha256sum --check --ignore-missing SHA256SUMS
```

У Windows ця команда пише `True`, якщо MSI збігається:

```powershell
(Get-FileHash .\dictum-0.4.0-win-x64.msi).Hash -eq ((Select-String 'win-x64.msi' .\SHA256SUMS).Line -split ' ')[0]
```

**Звіт VirusTotal.** В описі кожного випуску на [сторінці випусків](https://github.com/Sigil-build/dictum/releases) є розділ VirusTotal з посиланням для кожного файлу. [VirusTotal](https://www.virustotal.com/) перевіряє файл десятками антивірусів, а звіт показує, що знайшов кожен із них. Dictum поки не підписаний і ще мало відомий, тож один-два антивіруси можуть позначити його як підозрілий, хоча решта нічого не знаходить.

## Встановлення {#install}

Команди на цій сторінці написано для версії 0.4.0. Підставте версію, яку ви завантажили.

=== "Windows 11"

    **Інсталятор**

    1. Відкрийте `dictum-<version>-win-x64.msi`. Він нічого не питає.
    2. Якщо Windows покаже вікно "Windows protected your PC", натисніть **More info**, а потім **Run anyway** (в українській Windows ці написи перекладено). Див. [Якщо Windows блокує Dictum](#windows-blocks).
    3. Інсталятору не потрібні права адміністратора. Він встановлює Dictum лише для вашого користувача, у `%LOCALAPPDATA%\Programs\Dictum`, і додає Dictum до меню «Пуск».
    4. Наприкінці Dictum запускається й відкриває майстер налаштування. Далі — [перший запуск](#first-run).

    **Zip-архів, без інсталятора**

    1. Розпакуйте `dictum-<version>-win-x64.zip`. Усередині одна тека — `dictum-<version>-win-x64`.
    2. Перенесіть цю теку туди, де вона лишатиметься надовго, і дайте їй назву без версії, наприклад `C:\Tools\Dictum`. Тільки не в «Завантаження»: запуск під час входу запам'ятовує, де лежать програми, а оновлення кладеться в ту саму теку.
    3. Запустіть `dictum-gui.exe` із цієї теки. Dictum відкриє майстер налаштування.

=== "Linux"

    Виберіть один із трьох способів.

    **AppImage:** один файл, нічого не встановлюється.

    1. Перенесіть файл туди, де він лишатиметься надовго, дайте йому назву без версії й зробіть його виконуваним:

        ```sh
        mkdir -p ~/Applications
        mv ~/Downloads/dictum-0.4.0-linux-x64.AppImage ~/Applications/Dictum.AppImage
        chmod +x ~/Applications/Dictum.AppImage
        ```

    2. Запустіть його. Dictum відкриє майстер налаштування.

        ```sh
        ~/Applications/Dictum.AppImage
        ```

    Запуск під час входу запам'ятовує цей шлях, а оновлення замінює файл під тією самою назвою. Командний рядок теж усередині AppImage: допишіть `dictum` після назви файлу, наприклад `~/Applications/Dictum.AppImage dictum status`.

    **Архів tar.gz, для вашого користувача:** встановлюється в `~/.local/lib/dictum`.

    1. Розпакуйте архів і запустіть його `install.sh`:

        ```sh
        cd ~/Downloads
        tar -xzf dictum-0.4.0-linux-x64.tar.gz
        ./dictum-0.4.0-linux-x64/install.sh
        ```

    2. `install.sh` копіює Dictum у `~/.local/lib/dictum`, створює посилання `dictum` і `dictum-gui` у `~/.local/bin` і додає Dictum до меню програм. Права root йому не потрібні. Потім архів і розпаковану теку можна видалити.
    3. Запустіть Dictum з меню програм. Він відкриє майстер налаштування.

    **Arch Linux, CachyOS:** пакет для pacman, встановлюється в `/opt/dictum`.

    1. Покладіть `PKGBUILD` і `dictum-<version>-linux-x64.tar.gz` з одного випуску в одну теку.
    2. У цій теці виконайте:

        ```sh
        makepkg -si
        ```

        `makepkg` звіряє архів із сумою в `PKGBUILD`, збирає пакет `dictum-bin` і встановлює його через pacman, який попросить ваш пароль.

    3. Запустіть Dictum з меню програм. Він відкриє майстер налаштування.

## Якщо Windows блокує Dictum {#windows-blocks}

Інсталятор і програми Dictum поки не підписані, тож Windows про них попереджає:

- **SmartScreen** показує вікно "Windows protected your PC", коли ви вперше відкриваєте MSI або `dictum-gui.exe`. Натисніть **More info**, а потім **Run anyway**.
- **Smart App Control** блокує непідписані програми й не дозволяє зробити виняток для однієї з них. Поки ця функція ввімкнена, Dictum не вдасться ні встановити, ні запустити. Чи ввімкнена вона, видно в Windows Security → App & browser control → Smart App Control settings.

В українській Windows ці назви перекладено. Більше — у розділі [Розв'язання проблем](troubleshooting.md#smartscreen).

## Перший запуск: майстер налаштування {#first-run}

Під час першого запуску Dictum відкриває вікно **Майстер налаштування Dictum** із восьми кроків: **Мови**, **Модель мовлення**, **Чищення тексту**, **Ваші слова**, **Запуск під час входу**, **Що завантажити**, **Завантаження** і **Готово**. Ви вибираєте мови, якими диктуєте, а Dictum радить модель мовлення для вашої відеокарти чи процесора. Чищення тексту мовною моделлю й ваші слова — необов'язкові. Нічого не завантажується, доки ви не підтвердите список файлів, і кожен файл звіряється з його сумою SHA-256. Під час завантаження вікно можна закрити: завантаження триває далі й продовжиться після перезапуску. Кожен крок описано в [довіднику майстра налаштування](reference/setup-wizard.md).

Якщо закрити майстер, не дійшовши до кінця, він збереже ваші відповіді: виберіть **Налаштування** в меню трею, щоб відкрити його на тому самому кроці. Якщо закрити його під час завантаження файлів, він відкриється сам, щойно файли будуть на місці.

Далі Dictum живе в треї, біля годинника. Windows ховає нові значки за стрілкою ^, і крок **Готово** показує, як тримати значок Dictum на виду, щоб бачити, коли він записує. У GNOME для значка потрібне розширення «AppIndicator and KStatusNotifierItem Support».

## Перше диктування {#first-dictation}

1. Клацніть там, куди має потрапити текст: у текстовому редакторі, адресному рядку браузера, чаті.
2. Затисніть `Ctrl+Alt+Space`. Dictum подасть короткий сигнал, а невеликий індикатор унизу екрана покаже, що він слухає.
3. Говоріть.
4. Відпустіть клавіші. За мить текст з'явиться там, де стоїть курсор.

![Індикатор, поки Dictum слухає](images/overlay-listening.png#gh-light-mode-only)
![Індикатор, поки Dictum слухає](images/overlay-listening-dark.png#gh-dark-mode-only)

На кроці **Готово** майстер має поле **Спробувати диктування**, щоб спробувати це, перш ніж закрити вікно. Перше диктування після запуску Dictum чекає, доки модель мовлення завантажиться в пам'ять.

Якщо текст не з'явився, виконайте `dictum doctor` (у Windows — за повним шляхом, див. [Командний рядок](#command-line)) і загляньте в [Розв'язання проблем](troubleshooting.md#doctor). У програму, запущену від імені адміністратора, Dictum вставити текст не може: див. [Розв'язання проблем](troubleshooting.md#administrator).

## Wayland і X11 {#wayland-and-x11}

У Linux те, як Dictum отримує гарячу клавішу й вставляє текст, залежить від сеансу. Щоб дізнатися, який у вас сеанс, виконайте:

```sh
echo $XDG_SESSION_TYPE
```

- **X11:** гарячі клавіші й вставлення працюють без жодного налаштування.
- **Wayland:** програмі не дозволено самій стежити за клавіатурою чи натискати клавіші в інших програмах, тож Dictum звертається до порталу робочого столу, `xdg-desktop-portal`:
    - гарячу клавішу він реєструє через портал GlobalShortcuts, який мають KDE Plasma 6, GNOME 48 і новіші та Hyprland. Робочий стіл один раз попросить дозволити комбінацію;
    - Ctrl+V він натискає через портал RemoteDesktop. Робочий стіл один раз спитає, чи можна Dictum керувати клавіатурою, і Dictum запам'ятає відповідь. Без цього порталу Dictum бере `ydotool`, якщо його встановлено. У Sway та Hyprland порядок інший: спершу `wtype`, потім `ydotool`, потім портал.
- **Немає порталу GlobalShortcuts**, як у GNOME до версії 48: призначте в налаштуваннях клавіатури свого робочого столу клавішу на команду `dictum toggle`. Натисніть її один раз, щоб почати, і ще раз, щоб закінчити й вставити текст. У Sway можна тримати клавішу, поки говорите:

    ```text
    bindsym --no-repeat Ctrl+Alt+space exec dictum start
    bindsym --release Ctrl+Alt+space exec dictum stop
    ```

- **Термінали у Wayland:** Dictum не бачить, яка програма має фокус, тому скрізь вставляє через Ctrl+V. Терміналу ж потрібна Ctrl+Shift+V: зробіть для нього окремий профіль у Налаштуваннях → **Профілі** і в полі **Комбінація вставлення** виберіть Ctrl+Shift+V (див. [Налаштування](reference/settings.md#profiles)).

`dictum doctor` показує, що працює, а що треба встановити чи дозволити, якщо щось не працює.

## Налаштування без програми для робочого столу {#terminal-setup}

Якщо вам зручніше в терміналі або ваш робочий стіл не має трею, налаштуйте Dictum командою `dictum init` замість майстра:

```sh
dictum init
```

Вона ставить ті самі запитання одне за одним: ваші мови, модель мовлення, чищення тексту мовною моделлю, ваші слова і чи запускати Dictum під час входу. Потім показує список файлів і завантажує їх, коли ви погодитеся.

Після цього запустіть Dictum без програми для робочого столу, на передньому плані. `Ctrl+C` його зупиняє.

```sh
dictum daemon
```

Для гарячих клавіш і вставлення `dictum daemon` потребує сеансу робочого столу: Windows або Wayland чи X11 у Linux. Для скрипта `dictum init --yes` бере передані параметри, наприклад `--language "uk, en"`, а для решти — рекомендовані значення; їх перелічує `dictum init --help`.

## Командний рядок {#command-line}

У Linux архів tar.gz і пакет для Arch роблять `dictum` доступним у PATH. Якщо `~/.local/bin` у PATH немає, `install.sh` про це скаже. З AppImage допишіть `dictum` після назви файлу: `~/Applications/Dictum.AppImage dictum doctor`.

У Windows `dictum.exe` лежить поруч із `dictum-gui.exe`, але в PATH його немає. Після MSI запускайте його в PowerShell за повним шляхом:

```powershell
& "$env:LOCALAPPDATA\Programs\Dictum\dictum.exe" doctor
```

Після zip-архіву підставте свою теку, наприклад `& "C:\Tools\Dictum\dictum.exe" doctor`.

Щоб набирати просто `dictum`, додайте теку до змінної Path:

1. Відкрийте «Пуск», наберіть «environment» (або «змінні середовища») і виберіть **Edit environment variables for your account** — в українській Windows цей пункт перекладено.
2. У розділі **User variables** виберіть **Path** і натисніть **Edit**.
3. Натисніть **New**, введіть `%LOCALAPPDATA%\Programs\Dictum` (або теку з zip-архіву) і натисніть **OK** в обох вікнах.
4. Відкрийте нове вікно PowerShell і перевірте:

    ```powershell
    if (Get-Command dictum -ErrorAction SilentlyContinue) { 'dictum is on PATH' } else { 'dictum is not on PATH' }
    ```

## Запуск під час входу {#start-at-login}

Його вмикає крок майстра **Запуск під час входу**. Пізніше скористайтеся перемикачем **Запускати Dictum під час входу в систему** в Налаштуваннях → **Загальні**. Тоді під час входу запускається програма в треї, а вона запускає демон. Без програми для робочого столу `dictum daemon --install-autostart` запускає під час входу сам демон.

Із zip-архівом чи AppImage запуск під час входу запам'ятовує, де лежить Dictum. Якщо ви його перенесли, вимкніть запуск під час входу й увімкніть знову. Подробиці — у посібнику [Запуск під час входу](guides/start-at-login.md).
